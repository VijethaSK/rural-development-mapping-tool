# Smart Rural Infrastructure Management System
## Project Progress / Continuation Context

This is a final-year engineering project for:
Smart Rural Infrastructure Management Using Digital Mapping Technologies

The project is a web-based GIS platform for Panchayat-level infrastructure management.

## Core Objective

The system should go beyond simply displaying Panchayat infrastructure data.

It should provide:

1. Infrastructure Priority Scoring
2. Maintenance Route Optimization
3. Infrastructure Gap Detection
4. Complaint Heatmap Analysis
5. Budget-Based Recommendation
6. GIS-based infrastructure visualization
7. Citizen complaint management
8. Maintenance assignment and tracking

## Important Analytical Features

### 1. Infrastructure Priority Scoring

Each infrastructure receives a score based on multiple factors.

Road factors include:

- Condition
- Number of complaints
- Population served
- Traffic level
- Last repair/maintenance date
- Distance to alternative facility where applicable

The system should normalize factors before applying weights.

Example configurable weights:

condition: 0.30
complaints: 0.20
population: 0.15
traffic: 0.15
maintenanceAge: 0.10
alternativeDistance: 0.10

The score should be 0–100.

Priority levels:

0–39 = Low
40–59 = Medium
60–79 = High
80–100 = Critical

The UI should explain why an infrastructure received its score.

### 2. Route Optimization

Important:

Dijkstra must NOT be presented as solving the entire multi-stop route-ordering problem.

Use:

- Dijkstra for shortest paths between locations
- Greedy/nearest-neighbor strategy for initial multi-stop ordering
- 2-opt improvement where appropriate

The route should display:

- Starting point
- Maintenance stops
- Visit order
- Priority of each stop
- Total distance
- Estimated travel time
- Route polyline

### 3. Infrastructure Gap Detection

Identify areas that are underserved.

Example:

If the configured school accessibility threshold is 5 km, identify areas whose nearest school is beyond that threshold.

The threshold must be configurable.

### 4. Complaint Heatmap

Use actual complaint coordinates from MongoDB.

Support:

- Date filtering
- Category filtering
- Infrastructure type filtering
- Status filtering
- Priority filtering

### 5. Budget Recommendation

Given a fixed budget, recommend infrastructure maintenance projects based on:

- Priority score
- Estimated repair cost
- Population served
- Urgency
- Impact/cost efficiency

The total recommended cost must never exceed the available budget.

Recommendations must explain why projects were selected.

## Latest continuation record — Priority 3: GIS and routing correctness

- Road graph construction splits stored road segments at geometric intersections in a local equirectangular projection. Nodes merge only when coordinates agree at the documented 7-decimal coordinate key precision; no proximity connection radius is inferred. Endpoints snap to the nearest segment (maximum 5 km), and same-segment endpoints route directly along that segment. GeoJSON ordering remains `[longitude, latitude]`.
- Dijkstra results distinguish `NETWORK_ROUTE` from `STRAIGHT_LINE_FALLBACK`. Disconnected network components remain unreachable. Straight-line fallback distances are identified, are never reported as network distances, and produce no duration estimate. Multi-stop ordering remains priority-weighted nearest-neighbor followed by 2-opt; Dijkstra is used per leg and is not an exact multi-stop solver. Inputs are capped at 50 stops; duplicate IDs are removed, distinct colocated assets remain, and unreachable destinations are listed separately and excluded from route geometry.
- Route saves validate start coordinates and Panchayat-owned infrastructure, recalculate route order/geometry/distance/duration on the server, ignore supplied client metrics/geometry, and refuse routes with fallback or unreachable legs. Route metadata persists routing method/fallback status; legacy records are labelled `LEGACY_UNKNOWN`. Candidate routes use the contextual Panchayat center or stored infrastructure geometry; hardcoded Varthur route origins/default coordinates were removed.
- Gap analysis reports `WITHIN_THRESHOLD`, `BEYOND_THRESHOLD`, or `NO_FACILITY` for school and road coverage. Missing facilities score as Critical gaps instead of zero severity. Network distance is recorded only for actual network paths. Empty/degenerate grid bounds yield no cells, and grid creation is capped at 10,000 cells. Gap UI calls out missing facilities.
